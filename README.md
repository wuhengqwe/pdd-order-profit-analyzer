# 拼多多出单分析

按商品链接汇总订单量和估算利润，并根据规格编码和成交价格识别可以复用的模板。

[打开网站](https://wuhengqwe.github.io/pdd-order-profit-analyzer/)

## 使用方法

1. 从拼多多商家后台的「订单查询」导出「对账报表」。选择全订单状态和全售后状态，按需选择近 90 天。可以导入多个 CSV、Excel 或平台提供的 ZIP。
2. 从多多招财下载同一家店、同一时段的「推广商品」汇总报表。支持 CSV、XLS、XLSX，也支持带日期列的商品分天报表。推广费优先用总花费，缺列或单行为空时用成交花费。
3. 选择成本来源。默认在分析时读取原[链接盈亏分析工具](https://wuhengqwe.github.io/profit-analysis-tool/)当前公开的莆田和义乌成本快照。可以导入自有成本表或仅分析订单。自有表可包含「规格编码」「单位成本」「仓库」，按文本保留编码的前导零。
4. 默认莆田税点 1.5%、义乌税点 5%，可分别调整。查看模板清单、链接盈亏及规格价格，点击模板号查看成员。使用「模板最高单量链接」查看每组保留订单最多商品 ID 的订单和盈亏。在「链接盈亏」搜索任意商品 ID 后，可点该行模板号查看同组链接。通过「导出 Excel」保存完整分析，模板清单列出同组商品 ID，链接盈亏和最高单量分表列出每个商品的同组其他 ID、各自的保留单，以及按订单号去重的同组总单量。

输入订单、推广和自有成本文件在浏览器内处理。网站只在选用现有快照时读取公开成本文件。仓库不包含真实订单、报表或成本快照。

## 统计口径

- 有效成交排除未付款、已取消和退款成功记录。订单数按订单号去重，商品件数按订单行数量相加。一个订单涉及多个链接时，每个链接各计一单，整店只计一单，运费在关联链接间平摊。
- 规格成本先在莆田查找，找不到再查义乌。支持完整编码、套数、组合和义乌数字编码前导零。同仓多个价格冲突时该规格待核对。两仓都无法完整匹配组合时，分别匹配各组件。
- 按明确的发货仓计税。报表缺发货仓时按成本匹配的仓库识别，跨仓组合按仓库成本占比分摊实收。计税仓无法判定时利润留空。
- 估算利润为商家实收减商品成本、推广费、包装损耗、技术服务费、税点、运费和退款损耗预留。成本缺失、推广费不可归属、使用当期成本估算历史订单等情况会影响覆盖范围。
- 模板按实际成交过的全部规格编码与各规格常见商家实收单价归并。部分同码同价的链接可在「重叠规格」核对。

## 开发

静态网页位于 docs 目录，使用 GitHub Pages 从 main 分支的 /docs 发布，无需构建。可用 Python 在本机启动预览。

    python -m http.server 8420 --directory docs

回归检查使用 Node.js 20+。

    node --test

表格导入和导出使用 [SheetJS CE 0.20.3](https://docs.sheetjs.com/docs/getting-started/installation/standalone/)，ZIP 使用 [fflate 0.8.2](https://github.com/101arrowz/fflate)。版本固定并随站点服务，许可证在 docs/vendor。
